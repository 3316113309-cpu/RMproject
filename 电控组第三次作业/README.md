# 电控组第三次培训作业

- **李粤**
- **_20263001254_**

- 本次作业使用 STM32F103C8T6，实现三灯流水、按键控制、串口控制和 OLED 状态显示。上电后默认正向运行，切灯间隔为 300 ms，先点亮 LED1。

## 一、接线与工程配置

1. 使用 STM32CubeMX 配置工程，在 CLion 中编写和编译程序。
2. PA0、PA1、PA2 分别连接三颗 LED 的负极，LED 正极经过限流电阻接 3.3 V。输出低电平时灯亮，同一时刻只点亮一颗。
3. PB0 接方向按键，PB1 接暂停／继续按键；按键另一端接 GND。两个引脚都设置为内部上拉、下降沿外部中断。
4. USART1 的 PA9（TX）接 USB 转 TTL 模块的 RXD，PA10（RX）接模块的 TXD，双方共地。串口参数为 115200、8 位数据、无校验、1 位停止位。
5. OLED 使用软件 I²C：SCL 接 PB8，SDA 接 PB9，电源接 3.3 V 和 GND。培训资料中的原驱动使用 PB1/PB0，我把它改到了 PB8/PB9，避免与按键冲突。

## 二、程序的总体思路

1. 在 main.c 中用同一份状态记录是否运行、流水方向、切灯间隔和当前 LED 编号。按键和串口都修改这份状态，OLED 和反馈也从这里读取。
2. 每次切灯先关闭三颗 LED，再把当前 LED 对应的引脚拉低。正向顺序为 1→2→3→1，反向顺序为 1→3→2→1。
3. 主循环使用 HAL_GetTick() 判断是否到了切灯时间，没有用 HAL_Delay() 等待。暂停时保留当前亮灯；恢复后按当前方向和间隔继续。
4. 按键中断回调只记录按下事件，主循环做约 20 ms 消抖。PB0 每按一次切换正反方向，PB1 每按一次切换运行与暂停。
5. 串口通过 HAL_UART_Receive_IT() 逐字节接收。中断回调把字节放入缓冲区并继续开启接收；主循环用自定义的 CommandPacket 结构体解析和校验数据包。
6. OLED 显示 STATE、DIR、STEP、LED 四项状态。状态变化后刷新相应行，并补空格清除旧字符。
7. 有效串口命令或按键操作后，使用 HAL_UART_Transmit_IT() 发送状态反馈。正常切灯时不发送反馈。

## 三、串口数据包与反馈

- 串口助手的发送模式选 HEX，每次发送完整的六个字节，不添加换行：

    AA RUN DIR STEP_L STEP_H CHECK

- RUN：00 表示暂停，01 表示运行；DIR：00 表示正向，01 表示反向。
- STEP 是 100～2000 ms，低字节先发送。例如 300 ms 是 012C，因此发送 2C 01。
- CHECK 是前五个字节相加后保留低 8 位，即 (AA + RUN + DIR + STEP_L + STEP_H) % 256。
- 每包都会同时设置运行状态、方向和间隔；帧头、参数或校验和错误时，不执行命令。

例如：

- 运行、正向、300 ms：AA 01 00 2C 01 D8
- 运行、反向、300 ms：AA 01 01 2C 01 D9
- 暂停、反向、1000 ms：AA 00 01 E8 03 96

我定义的反馈为一行英文文本，末尾带回车换行；串口助手接收区选择文本模式即可查看：

    STATE=RUN,DIR=FWD,STEP=300,LED=1

其中 STATE 为 RUN 或 PAUSE，DIR 为 FWD 或 REV，STEP 为毫秒数，LED 为当前亮灯编号 1～3。

## 四、测试与思考

- 实板已验证三灯依次点亮、OLED 四行显示和两只按键的切换功能。
- 串口已验证运行／暂停、正向／反向、300 ms／1000 ms 设置及状态回传。校验和错误的数据包不会改变状态。
- 如果把切灯间隔设为 2000 ms，同时用 HAL_Delay(2000) 等待，主循环就不能及时处理按键和串口。这里使用 HAL_GetTick() 记录时间，主循环仍持续处理输入，所以长间隔不会造成同样的等待。
- 本工程完成的是软件 I²C 和串口中断发送的基础要求；未做硬件 I²C 或 DMA 发送选做。
